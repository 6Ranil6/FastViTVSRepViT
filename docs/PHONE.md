# Установка и проверка на Samsung Galaxy A34 5G

Если пакет с FastViT-SA12 и RepViT-M0.9 уже собран, начните с шага 2. В свежей копии проекта сначала подготовьте модели по инструкции обучения и экспорта. После обновления моделей нажмите Run, чтобы переустановить приложение. [Обучение и экспорт](TRAIN_EVAL.md)

1. На Mac завершите обучение и экспорт обеих моделей и выполните из корня проекта:

   ```bash
   source .venv/bin/activate
   python -m coursework.bundle --seed 42
   ```

   Сценарий `scripts/run_experiment.sh` уже собирает этот пакет после экспорта.

2. Установите [Android Studio](https://developer.android.com/studio). В SDK Manager установите Android SDK Platform 35 и Build Tools 35.0.0. Откройте **папку `android`**, дождитесь Gradle Sync. Выберите встроенный JDK Android Studio (не ниже 17; Gradle 8.11.1 поддерживает JDK 21).

3. На Samsung: «Настройки → Сведения о телефоне → Сведения о ПО», нажмите семь раз «Номер сборки». Включите «Параметры разработчика → Отладка по USB». Подключите телефон кабелем с передачей данных и подтвердите отладку на экране телефона.

4. В Android Studio выберите физический Samsung и нажмите **Run ▶**. Приложение работает офлайн, разрешение на интернет ему не нужно.

5. В приложении выберите **1 поток**, нажмите «Сравнить модели». Будут выполнены по 30 прогревов и 200 измерений каждой модели, а также проверка 102 тестовых фото. Дождитесь сообщения «Готово», затем **«Сохранить CSV»**.

6. Дайте телефону остыть. Повторите не менее трёх раз, чередуя флажок «Сначала RepViT». Проведите отдельную серию с 4 потоками. Оставляйте одинаковые яркость, режим питания и условия зарядки; закройте фоновые приложения. Не сравнивайте один холодный запуск с другим на перегретом телефоне.

В CSV есть сырые задержки каждого вызова, p50/p95, точность на подвыборке, macro-F1, совпадение с эталоном Mac, SHA-256 моделей, размер `.pte`, время загрузки, PSS и thermal status. Метрики p50/p95 включают вызов Java/JNI `forward`, но исключают чтение/нормализацию фото. Это не FPS камеры и не end-to-end время приложения.

Для отчёта объедините мобильные результаты с `runs/report/comparison.csv`. Сравнивайте одну и ту же контрольную сумму модели между прогонами. Строки `reference_agreement` должны быть 1.0; расхождения требуют проверки, а не объяснения качеством обучения.

Сохраните CSV в папку `phone-results` в корне проекта и выполните:

```bash
python -m coursework.mobile_report phone-results/*.csv
```

Получится `runs/report/mobile_comparison.csv`: среднее и стандартное отклонение p50 по сериям, средняя p95. Скрипт разделяет разные устройства, количество потоков и SHA-256 моделей; отвергает незавершённые прогоны и нарушения совпадения с эталоном. Нагретые серии не удаляются автоматически — анализируйте thermal status.

## Через терминал после настройки SDK

```bash
cd android
./gradlew assembleDebug
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ru.bmstu.flowers/.MainActivity
```

Если приложение установлено debug-сборкой, последний завершённый CSV можно забрать:

```bash
adb exec-out run-as ru.bmstu.flowers cat files/last_results.csv > phone-results.csv
```

## Если что-то не работает

- **SDK location not found:** откройте проект Android Studio либо укажите `sdk.dir=/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/Library/Android/sdk` в `android/local.properties`.
- **Нет bundle:** выполните экспорт двух моделей и `coursework.bundle`, затем пересоберите APK. Assets копируются при сборке.
- **Телефон unauthorized:** разблокируйте экран и подтвердите RSA-ключ отладки. Не используйте эмулятор для измерений курсовой.
- **Gradle не скачивает зависимости:** нужен доступ к Google Maven, Maven Central и services.gradle.org; это этап сборки, не работы приложения.
- **Ошибка контрольной суммы или логитов:** пересоберите bundle и APK из одних и тех же экспортов. Версия Python ExecuTorch и Android runtime должна оставаться 1.0.0.
- **Нагрев / высокая p95:** дождитесь охлаждения и повторите серию; не удаляйте медленные измерения без заранее заданного правила.

В этой версии используется CPU XNNPACK. Наличие MediaTek в телефоне само по себе не означает, что модель работает на NPU. Проверка NPU потребовала бы отдельного бэкенда, SDK и проверки поддержки устройства.
